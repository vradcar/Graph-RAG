# Phase 3 — UI Design Contract

> Visual and interaction contract for the Streamlit web interface.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> Stack note: This is a Streamlit 1.35.x application. There is no CSS framework,
> no component library, and no custom design token system. All visual decisions
> are expressed as Streamlit widget choices, layout decisions, and copy strings.
> "Spacing" and "typography" sections below describe Streamlit's built-in defaults
> that the executor must not override — not custom CSS values.

## Page Configuration

```python
st.set_page_config(
    page_title="Honeywell T9 GraphRAG",
    page_icon="🌡️",
    layout="wide",          # wide chosen: sidebar + main area need horizontal room
    initial_sidebar_state="expanded",
)
```

Rationale for `layout="wide"`: The sidebar holds persistent controls (Neo4j link, depth
slider, provider/model display). `centered` layout clips the sidebar on smaller screens
and leaves the main content too narrow for prose + expander. `wide` gives both zones
comfortable width at typical laptop resolutions (1280px+).

## Spacing Scale

Streamlit manages all layout spacing internally. Do not inject custom CSS `margin`,
`padding`, or `gap` values via `st.markdown("<style>…</style>", unsafe_allow_html=True)`
unless a specific exception is listed below.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | (Streamlit internal — not overridden) |
| sm | 8px | (Streamlit internal — not overridden) |
| md | 16px | (Streamlit internal — not overridden) |
| lg | 24px | (Streamlit internal — not overridden) |
| xl | 32px | (Streamlit internal — not overridden) |
| 2xl | 48px | (Streamlit internal — not overridden) |
| 3xl | 64px | (Streamlit internal — not overridden) |

Exceptions:

- Demo query buttons: render in `st.columns(3)` to place them side-by-side in a
  single row. Each column receives one `st.button`. This is a layout decision, not
  a spacing override.
- Sidebar divider: use `st.sidebar.divider()` between the Neo4j button + depth slider
  group and the read-only provider/model display group.

## Typography

Streamlit uses Inter (loaded from CDN) at its default scale. Do not override font
family or size via custom CSS. The roles below map to Streamlit's own widget hierarchy.

| Role | Streamlit Widget | Effective Size | Weight | Line Height |
|------|-----------------|----------------|--------|-------------|
| Page title | `st.title()` | ~2rem | 700 | 1.2 |
| Section label | `st.subheader()` | ~1.25rem | 600 | 1.3 |
| Body / prose | `st.write()` / `st.markdown()` | 1rem (16px) | 400 | 1.5 |
| Caption / meta | `st.caption()` | 0.875rem (14px) | 400 | 1.4 |

Use `st.title()` for the app heading only. Use `st.write()` for all answer prose.
Do not use `st.header()` or `st.subheader()` for answer content — keep the visual
hierarchy flat inside the answer area.

Source: Streamlit 1.35.x default theme; not overridden.

## Color

Streamlit's default light theme is used unchanged.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #FFFFFF (Streamlit default) | Page background, main area |
| Secondary (30%) | #F0F2F6 (Streamlit default sidebar) | Sidebar background |
| Accent (10%) | #FF4B4B (Streamlit default primary) | Submit button ("Ask") only |
| Info | #1C83E1 (Streamlit default info) | `st.info()` not-found banner |
| Error | #FF4B4B (Streamlit default error) | `st.error()` backend failure message |

Accent (#FF4B4B) reserved for: the primary "Ask" submit button only. Demo query
buttons use Streamlit's secondary button style (`st.button(label, type="secondary")`
or default `st.button`) — they must not use `type="primary"` to avoid three red
buttons competing with the main CTA.

Do not set a custom `[theme]` block in `.streamlit/config.toml`. If a config file
is needed for other settings (e.g. server port), the `[theme]` section must be
absent.

| Error message | `st.error(friendly_message)` | Rendered when backend raises exception. Raw traceback must not be shown. |

## Session State Contract

Demo query button behavior requires session state to bridge two Streamlit reruns
(button click sets the input value; submit fires on the same rerun via a flag).

```python
# Initialise once at app startup
if "pending_question" not in st.session_state:
    st.session_state.pending_question = ""

# Demo buttons write to session_state and set a submit flag
if st.button("What accessories are compatible with the T9?"):
    st.session_state.pending_question = "What accessories are compatible with the T9?"
    st.session_state.auto_submit = True

# text_input reads from session_state as default value
question = st.text_input("Your question", value=st.session_state.pending_question, key="question_input")

# Submit fires on explicit button OR auto_submit flag
submit = st.button("Ask", type="primary") or st.session_state.get("auto_submit", False)
if submit:
    st.session_state.auto_submit = False   # clear flag
    # … run pipeline …
```

This pattern avoids `st.rerun()` calls and keeps the input pre-populated with the
demo question when the answer renders.

## Caching Contract

```python
@st.cache_resource
def load_settings_cached():
    """Load settings.yaml once per process. Avoids repeated disk reads."""
    return load_settings()
```

The `Neo4jGraphStore` and instructor client are instantiated inside
`run_query_structured()` which already manages its own connection lifecycle. Do not
wrap `run_query_structured()` itself in `@st.cache_resource` — each query must open
a fresh Neo4j session. Settings loading is the only candidate for caching.
